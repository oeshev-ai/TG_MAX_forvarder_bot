# Telegram ↔ MAX Forwarder Bot

> Двусторонний бот, который синхронизирует посты между парами каналов Telegram и MAX: текст, медиа, правки и удаления.

## Проблема

Бизнесу и авторам каналов нужно вести аудиторию и в Telegram, и в MAX. Ручной кросспост съедает время: медиа и разметка часто «ломаются», правки не доезжают до второй площадки, а при обратной пересылке легко получить дубли и петли.

## Решение

Бот связывает каналы парами через одноразовый код в личке, слушает оба Bot API (long polling) и пересылает посты в обе стороны. Сообщения мапятся по id, свои же пересылки отфильтровываются, чтобы не было цикла TG → MAX → TG. Очередь с retry и backoff держит пики и временные сбои API.

Поддерживаются текст, фото, видео, документы, аудио, альбомы, базовая HTML-разметка, правки в обе стороны и удаления MAX → Telegram.

## Что внутри

- Технологии: Python 3.11, aiogram 3, maxapi, aiohttp, python-dotenv, Docker Compose
- Архитектура: dual polling (Telegram + MAX) → handlers → очередь (до 3 задач) → send/edit/delete + mapping в `data/`
- Деплой: VPS + Docker Compose (`restart: unless-stopped`, volume `./data`)

## Как запустить

```bash
git clone https://github.com/oeshev-ai/TG_MAX_forvarder_bot.git
cd TG_MAX_forvarder_bot
cp example.env .env  # заполните TELEGRAM_BOT_TOKEN и MAX_BOT_TOKEN
docker compose up -d --build
```

Пары каналов связываются в личке бота (`/start` → код на 10 минут) и хранятся в `data/channel_pairs.json` без перезапуска. Оба бота должны быть админами/с правом писать в своих каналах.

## Результат

- Один пост публикуется в оба канала без ручного копирования
- Правки и удаления не расходятся с оригиналом (mapping сообщений)
- Пары каналов связываются без правки `.env` и без рестарта сервиса
